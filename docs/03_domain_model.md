# 03 ドメインモデル — スキルじゃんけんラボ

2026-10-26改訂。[ADR 0003](adr/0003-remove-synthesis.md)によりスキル合成を廃止した。以下は新仕様であり、現行Web v2のコード・保存データへの反映済みを意味しない。旧企画は[アーカイブ](archive/README.md)を参照する。

## 用語・初期状態

| 用語 | 定義 |
|---|---|
| 仲間 | Charactersのキャラクター種類。個体差・レベルなし |
| 所有 | その仲間を選べること。同じ種類を複数所有しない |
| 習得 | S01〜S03が初期状態から使える固定状態。追加解放なし |
| 適性 | CharacterSkillsのキャラクターとスキルの対応 |
| 使用可能 | 所有する仲間に適性があり、初期習得済みのスキルであること |
| 装備 | 対戦要求で選ぶスキル1つ。次回の初期選択は端末内だけで保持 |
| 探究ポイント | 対戦で積み上がる累計スコア。消費・交換・購入・解放条件なし |

初期プレイヤーはP001「たんけんたい」。C01所有、S01〜S03習得、points=0、version=0。名前変更・プレイヤー作成の画面は設けない。

## 初期マスターとゲームルール

### キャラクター

| ID | 名前 | 使えるスキル | 標準の図形 |
|---|---|---|---|
| C01 | ひのこ | S01・S02 | 炎 |
| C02 | しずく | S02・S03 | しずく |
| C03 | このは | S01・S03 | 葉 |

見た目と適性が異なる。属性相性・攻撃力・HP・レア度は設けない。適性は6行で固定し、仲間獲得や対戦では増減しない。

### スキル

| ID | 名前 | 効果コード | 発動条件 | 加算 |
|---|---|---|---|---:|
| S01 | かちのひらめき | WIN_BONUS | 勝ち | +1 |
| S02 | まけてもいっぽ | LOSE_BONUS | 負け | +1 |
| S03 | あいこのわ | DRAW_BONUS | あいこ | +1 |

装備は1つ。適性のないスキルやスキルなしの対戦は受け付けない。合成・S04・R01・常時加算は廃止。初期3種をそのまま使い分ける。

## 機能別の条件と結果

### F01 起動・再開

- 本人限定Webアプリでマスター・P001の最新状態・採用済みセリフ集を取得する。
- 状態を読めるまで変更ボタンを無効にする。初回は初期状態、以後は最新の保存状態を表示する。
- ゲーム記録不整合は変更停止。自動初期化や過去行への巻戻しを行わない。
- 旧masterVersion=1のブックは新ゲームへそのまま書き込まず、提供者へ新仕様の準備を案内する。旧記録の保管・検証は[データモデル](05_data_model.md)に従う。

### F02 なかまをよぶ

- 未所有かつ有効な仲間からサーバーで等確率に1体を選ぶ。費用0。
- 初回はC02/C03各50%、2回目は残り1体100%。全3体所有時は「みんなそろったよ」と表示し、抽選ボタンを完了表示へ置き換える。
- 結果と所有追加を保存してから、図形と表情の仲間カードをすぐ表示する。時間待ちの演出は追加せず、「このなかまとあそぶ」で獲得した仲間を選んだ対戦画面へ進める。
- 候補数を確率説明に使う。クライアントから結果や乱数を受け取らない。

### F03 じゃんけん

1. 所有仲間1体と適性のあるスキル1つを選ぶ。
2. グー・チョキ・パーをローカルで選び、「この手でじゃんけん！」を押したときだけ1対戦の要求を送る。手が未選択なら決定できない。
3. サーバーで所有・習得・適性・入力・状態版を検証し、CPUの手を各1/3で選ぶ。
4. 勝敗・得点・次状態を計算する。入力・抽選結果を1件の行動として保存し、計算値は履歴から復元する。
5. 自分とCPUの手、勝敗、基本点・加算・獲得点、累計スコア、読込済みセリフを表示する。

手はrock / scissors / paper。同じ手はDRAW、グーはチョキ、チョキはパー、パーはグーに勝つ（WIN）。残りはLOSE。スキルによる再抽選・勝敗変更はない。

| 勝敗 | 基本点 | 対応スキルが発動した場合の獲得点 |
|---|---:|---:|
| WIN | 2 | 3 |
| DRAW | 1 | 2 |
| LOSE | 1 | 2 |

条件不一致の加算は0。pointsは全ROUNDのearnedPointsの合計であり、抽選・画面移動・管理操作では変わらない。再送で二重加算しない。ポイントの消費先や別の成長機能は追加しない。

### F04 廃止

旧合成機能の番号は欠番とする。UI・API・新規記録の生成経路に合成を残さない。旧記録の検証処理はゲーム機能とは分離する。

### F05 つながりをみる

- Players→Actionsの1対多をP001の最新10件で表示する。
- Characters3体×Skills3種の対応表を実データから作る。6本の適性を表示し、キャラまたはスキルの選択で関連を強調する。
- 未所有の仲間も対応表に表示するが、未所有と明示して対戦選択不可にする。
- 3スキルはすべて最初から習得済み。習得の鍵や合成前後の切替は設けない。
- 仲間を獲得しても6本の線は変わらず、所有表示だけが変わる。各スキルを2体の仲間が使えることを説明する。

### F06 画像なしのカード表示

仲間3体・スキル3種の計6カードをHTML/CSS・名前・効果文で識別する。画像ファイル・getAsset・画像生成は不要。色だけに依存しない。

### F07 事前生成したAIセリフ

提供者用管理画面で仲間3体×勝敗3種の9枠を事前生成・確認・採用する。各枠最大3文・各40文字以内。ここでの9枠は適性6行とは別物である。

ゲームはbootstrapで採用集を読み込み、保存成功後にキャラと勝敗からブラウザ内で選ぶ。採用文がなければ定型文。プレイ中の生成・セリフ専用RPCは禁止。詳細は[AIセリフ設計](specs/ai-battle-dialogue.md)。

## 状態とライフサイクル

| 状態・操作 | 更新されるもの | 変わらないもの |
|---|---|---|
| 初期状態 | C01所有、S01〜S03習得、points 0、version 0 | 適性6行 |
| DRAW成功 | 未所有1体追加、version +1、Actions 1行 | points・習得・適性 |
| ROUND成功 | 獲得点を累計加算、version +1、Actions 1行 | 所有・習得・適性 |
| 読取・拒否 | 変更なし | 全ゲーム状態 |
| 同一要求の再送 | 保存済みresult/stateを返す | 乱数・状態・Actionsを再更新しない |
| 管理画面の事前生成・公開 | 管理用データのみ | 全ゲーム状態・Actions |
| 不完全行 | 利用を停止し提供者へ案内 | 自動初期化・巻戻しなし |

DRAWは行動typeでは仲間抽選、outcomeではあいこを表す。通信失敗は結果未確定であり、同じ要求を再送して解決する。新規ActionsはDRAW / ROUNDだけ。旧SYNTHESISを削除・改変して新仕様へ読み替えない。
