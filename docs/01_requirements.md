# 01 要件 — スキルじゃんけんラボ

反映日：2026年10月26日。初期資料（退避済み）：[01_企画書.md](archive/スキルじゃんけんラボ_企画・仕様・設計/01_企画書.md)・[02_仕様書.md](archive/スキルじゃんけんラボ_企画・仕様・設計/02_仕様書.md)（v1.0）。

本書は現行仕様を定義する。ローカル実装・検証済み範囲と未完了の実環境確認は[最新記録](tasks/03_active/mvp-release-verification.md)および[テスト戦略](07_test_strategy.md)で区別する。参照元と本書の役割・更新規約は[索引](00_index.md)を参照。

## 目的

提供者本人が、まず「遊べて、仕組みを見せられるゴールアプリ」を1日程度で作る。その完成物を教材づくり・子どもへの試遊・将来のサービス検討の出発点にする。最初から教材販売基盤や大規模ゲーム運営を作らない。

子どもがキャラクターを集め、スキルを選び、じゃんけんをして、仲間ごとに使えるスキルや得点の違いを試す。遊びの裏にある「1人に複数の記録」「1体に複数のスキル／1つのスキルを複数のキャラクターが使う」を可視化し、1対多・多対多のリレーションを学ぶ入口にする。

将来のECサイトの「顧客と注文」、管理画面の「ユーザーと役割」へつながる理解を目指す。初回からSQLや正規化の用語を覚えさせることは目的にしない。

以下の根拠の記述は企画書から引き継いだもの。本監査で参照チャットを再取得・再確認したものではない。

参照元：[ゲーム企画支援](chatgpt-conversation://6ade90d5-921c-83e8-b6d1-fb7b70606520)

参照チャットから確認できた要望は、提供者が先にゴールアプリを作ること、1日程度という開発感覚、GASアプリへのスキル合成・Geminiイラストの紐付け、WebP表示、1対多・多対多の学習、巨大・複雑にしないことである。参照チャットの過去のアシスタント本文は取得結果に含まれなかったため、過去に詳細仕様が合意済みとは扱わない。

上記は初期企画の経緯であり、画像生成と合成は[ADR 0003](adr/0003-remove-synthesis.md)までの後続指示で廃止した。

以下は今回の設計提案であり、ユーザーの過去の確定発言ではない。

| 項目 | 初版の前提 |
|---|---|
| 対象 | 小学校中〜高学年を仮対象。大人が伴走する |
| 提供形態 | 提供者自身のGoogleアカウントで開く、管理端末上の試遊 |
| プレイヤー | 仮名のデモプレイヤー1人。交代して遊ぶ場合は同じ記録を使う |
| 端末 | スマートフォンの縦画面を中心とするWebアプリ |
| 開発者 | GAS・JavaScript・Sheetsの基本を扱える提供者1人 |
| 1日の意味 | 準備済みGAS・Sheets環境で約8時間を使える目標値。画像生成環境は不要 |
| 生成AI | 管理画面でキャラ×勝敗の短文を事前生成・確認・採用。ゲーム中の生成は禁止。採用文がなければ定型文 |
| 公開範囲 | 初版は本人限定。子どもが各自の端末から参加する公開サービスは次段階 |

本人限定公開は、独立した子どもアカウント・認証・同意管理を1日に詰め込まないための設計判断。提供者アカウントの認証情報を子どもに配布せず、管理端末でアプリだけを見せる。

## MVPの範囲

| 初日に必ず完成するもの | 内容 |
|---|---|
| キャラクター | 3体。最初に1体、残り2体を無料抽選で獲得 |
| スキル | 基本3種を初期習得。適性のある1つを装備。追加解放なし |
| 対戦 | CPUとの1手完結じゃんけん。HP・属性相性・ターン制なし |
| スコア | 対戦で得た点を累計表示。消費・交換・購入・解放条件なし |
| 保存 | 所有・累計スコア・行動記録をSheetsに保存 |
| カード表現・AI | 図形・名前・効果文で表示。管理画面で事前生成・採用した一言を結果に合わせて表示 |
| 学習 | 1対多の記録一覧、多対多のキャラ―スキル対応表 |
| 運用 | 本人限定公開、二重実行対策、AI停止時の定型セリフ、バックアップ手順 |

初日に作らないもの：課金、広告、対人戦、ランキング、チャット、ユーザー登録、自由入力プロンプト、子どもによる画像生成、スキル合成、生成AIによるゲーム効果決定、リアルタイム同期、教材販売、保護者管理画面。ただし提供者本人用のセリフ制作管理画面はF07の範囲に含む。


初版は1端末・P001の1プレイヤー・同時変更1件・成功した行動記録200件までの短期デモ。一般公開、学校全体での同時利用、独立した子どもアカウントは対象外。

## 子どもが体験する価値

1. 「なかまをよぶ」で新しい仲間カードが出る。
2. キャラクターとスキルを1つずつ選ぶ。
3. グー・チョキ・パーを選び、「この手でじゃんけん！」でCPUと1回勝負する。
4. 勝敗とスキルによって探究ポイントが増える。
5. 仲間や適性のあるスキルを変えて、得点の違いを試す。
6. 「つながりをみる」で、同じスキルが複数の仲間につながることに気づく。

負けても基本ポイントを得られる。スキルは勝敗を書き換えず、ポイントにだけ作用するため、じゃんけんの理解を妨げない。

## Critical User Journey / Golden Path

一次ユーザーは大人と管理端末で試遊する子ども。仲間獲得からスキル選択・対戦・学習表示までを完走し、再読込後も結果が残ることを完成状態とする。新規デモデータで開始する。

| # | ステップ | 成功条件（観測可能な状態） |
|---|---|---|
| 1 | 本人限定URLで起動 | P001、C01、S01〜S03、0ポイント、version 0 |
| 2 | 「なかまをよぶ」を2回 | 重複なしで全3体。次の抽選は無効 |
| 3 | C01とS01でじゃんけんし、仲間・適性スキルを変えて試す | 勝敗・基本点・加算が保存され、累計スコアが増える |
| 4 | 「つながり」を見る | 最新10件と3体×3種・6本の適性が実データに一致。所有表示と適性を区別 |
| 5 | 再読込・再開 | version・累計スコア・所有・初期習得3種が一致 |

構成要素との対応は[アーキテクチャ](02_architecture.md)、実機での確認手順は[リリース手順](08_release_runbook.md)、合否の詳細は[テスト戦略](07_test_strategy.md)を参照する。

## 学習体験

| 学習テーマ | ゲーム内で見るもの | 大人が添える問い | 業務アプリへの接続 |
|---|---|---|---|
| 1対多 | 1人のプレイヤーに複数の行動記録 | 「この人の記録は何件ある？」 | 顧客1人と複数の注文 |
| 多対多 | キャラクター3体とスキル3種の対応表 | 「このスキルを使える仲間は何体？」 | ユーザーと役割、商品とカテゴリ |
| 中間テーブル | CharacterSkillsの1行が1本の線 | 「仲間の表にスキル名を全部詰めたらどうなる？」 | 関連付けを独立した表にする |
| 参照の一貫性 | 名前を変えてもIDの線は変わらない | 「同じ名前が2つあったら？」 | 主キー・外部キーの入口 |
| 固定ルール | スキルの発動条件と得点の対応 | 「同じ勝敗でも選ぶスキルで点はどう変わる？」 | 入力検証・業務ルール |

子どもが遊ぶ段階では短い言葉と絵を優先する。大人と仕組みを見る段階でIDや表名を表示する。キャラクター間のバトルを「多対多」と呼ぶのではなく、データの対応関係を学ぶ。

## 画面・アクセシビリティ

4画面＋結果モーダルで構成する。下部に「ホーム／なかま／じゃんけん／つながり」を1列で配置する。ホームは対戦への入口を主役にし、保存状態はコンパクトな共通欄へまとめる。画面幅に応じた配置、状態ごとの操作、管理画面の詳細は[UI/UX設計](specs/uiux-redesign.md)を正本とする。

| ID | 画面 | 主な表示 | 操作と遷移 |
|---|---|---|---|
| UI01 | ホーム | 選んだ仲間、遊びの案内、収集状況。合計ポイントはヘッダー | 主操作はじゃんけんへ。無料抽選と発見への問いを補助配置 |
| UI02 | なかま | 図形と表情の3体、所有状態、適性、収集数 | 所有仲間であそぶ→対戦。未所有は選べない。全員集合後は抽選を完了表示へ変更 |
| UI03 | じゃんけん | 仲間→スキル→手の3段階と選択確認。得点説明は折りたたみ | 手の選択は通信なし。決定→保存→結果。「もういちど」は未選択の手へ戻り自動送信しない |
| UI04 | 廃止・欠番 | 合成画面は設けない | 旧URL・操作からも合成不可 |
| UI05 | つながり | 条件名を表頭にした対応表、発見文、最新10件、大人向け補足 | 行・列の選択を強調し文章で説明。履歴の絞込みと0件案内 |

通信中はすべての状態変更操作と仲間・スキル・手の選択を無効にする。結果は手・得点内訳・セリフを示し、獲得結果から獲得した仲間で対戦へ進める。戻る操作は表示の切替だけで、送信済み要求を取り消さない。タブへの復帰・ブラウザー履歴からの復帰時はサーバー状態を取得する。アプリ内の4画面切替は取得済み状態を使い、通常対戦の通信を増やさない。保留要求があるときは自動送信せず手動解決する。結果モーダル表示中の更新は閉じるまで待つ。

### UIの共通条件

- 360px幅の縦画面で横スクロールを生じさせない。対応表は省略名と詳細表示で収める。
- 主ボタンのタップ領域は縦横44px以上、本文は原則16px以上。
- 図形と名前のカードを主役にし、説明は短い日本語。難しい用語は学習欄だけで補足する。
- 色だけで勝敗や所有を表現しない。文字・記号を併用する。
- 画像には代替テキスト。ボタンに読み上げ可能な名前。結果・エラーは読み上げ通知する。
- 音声は初版なし。動きを減らす端末設定では演出を省略する。
- パソコンではキーボードでボタンを選択でき、結果を閉じたら操作元へフォーカスを戻す。

## 完成の定義

- スマートフォンで、仲間獲得→装備選択→じゃんけん→つながり確認、を完走できる。
- ポイントと所有状態が再読込後も維持され、同じ要求の再送で二重加算されない。
- 画像素材なしで仲間3体・スキル3種を識別し、全ゲーム操作と学習表示を完走できる。AIセリフの実生成を確認し、AI無効・上限・障害でも定型文で継続する。
- 学習画面の表示がSheetsの実データと一致する。
- 提供者本人以外のGoogleアカウントからアクセスできないことを確認する。
- 仕様書由来の受入条件と結果は[テスト戦略](07_test_strategy.md)に記録する。本文書は設計成果物であり、アプリの実装・試験完了を示すものではない。

## 試遊で観察すること

初回は提供者の説明付きで5〜10分。子どもの氏名・年齢・写真は記録せず、「次に押す場所が分かったか」「スキルと得点の関係を説明できたか」「同じスキルが複数の仲間につながることに気づいたか」を提供者がメモする。

学習効果や継続率を保証する企画ではない。試遊を通して、楽しさとリレーションの理解が両立するかを確かめる。

## 運用と将来拡張の優先順

初版の想定は1端末・1プレイヤー・同時操作1件、行動記録200件までの短期デモ。一般公開や学校全体での同時利用は対象外。

次段階の優先順は、①複数のデモデータで教材を作る、②安全な個別認証とプレイヤー分離、③教室での限定運用、④必要になった場合のDBへの移行。公開前には対象者、同意・削除の流れ、利用規約、利用するGoogleサービスの条件、問い合わせ窓口を具体的な運用に合わせて確認する。

画像生成は製品から廃止し、将来拡張の待機項目にも置かない。AIの対象は短い対戦セリフに限定する。無限のスキル生成は効果の整合性を崩すため対象外。

## 仕様変更の境界

キャラ・基本スキルを増やす場合は、ID参照、適性、確率表示、画像、受入条件を一緒に更新する。対戦効果は定義済み効果コードだけを扱い、Sheetsの任意コードやAI出力を実行しない。

複数プレイヤー、子ども本人によるログイン、公開アクセス、リアルタイム生成は本書の範囲外。初版の公開設定を緩めるだけでは対応できない。
