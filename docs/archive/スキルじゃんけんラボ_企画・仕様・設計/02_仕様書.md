# 仕様書：スキルじゃんけんラボ

版：1.0 ／ 作成日：2026年10月26日 ／ 対象：本人限定・1プレイヤーのMVP

関連文書：[企画書](01_企画書.md)・[設計基礎書](03_設計基礎書.md)

本書の数値・名称は実装可能にするための初期提案。ゲーム動作は本書、保存・通信は設計基礎書を正とする。未実装の設計であり、試験結果はすべて未実施。

## 1. 用語・初期状態

| 用語 | 定義 |
|---|---|
| 仲間 | Charactersに登録されたキャラクター種類。個体差・レベルなし |
| 所有 | プレイヤーがその仲間を選べること。同じ種類を複数所有しない |
| 習得 | プレイヤー全体でスキルが解放されていること |
| 適性 | CharacterSkillsでキャラクターとスキルが結び付いていること |
| 使用可能 | 習得済み、かつ選択キャラクターに適性があること |
| 装備 | 対戦リクエストで選ぶスキル1つ。次回の初期選択は端末内だけで保持 |
| 探究ポイント | 対戦で獲得し、合成で使う整数。現金・商品への交換なし |

初期プレイヤーはP001「たんけんたい」。所有はC01のみ、習得はS01・S02・S03、ポイント0、状態バージョン0。名前変更・プレイヤー作成の画面は設けない。

## 2. マスターの初期値

### 2.1 キャラクター

| ID | 名前 | 基本適性 | 合成後に使えるスキル | 画像ID |
|---|---|---|---|---|
| C01 | ひのこ | S01・S02 | S04 | A_C01 |
| C02 | しずく | S02・S03 | S04 | A_C02 |
| C03 | このは | S01・S03 | S04 | A_C03 |

キャラクターの見た目と適性だけが異なる。属性相性、攻撃力、HP、レア度は存在しない。

### 2.2 スキル

| ID | 名前 | 効果コード | 発動条件 | 加算 | 画像ID |
|---|---|---|---|---:|---|
| S01 | かちのひらめき | WIN_BONUS | 勝ち | +1 | A_S01 |
| S02 | まけてもいっぽ | LOSE_BONUS | 負け | +1 | A_S02 |
| S03 | あいこのわ | DRAW_BONUS | あいこ | +1 | A_S03 |
| S04 | たんきゅうのひかり | ALWAYS_BONUS | すべての結果 | +1 | A_S04 |

スキルは1つだけ装備でき、重ねがけしない。基本スキルを持っていても、選んだ仲間に適性がなければ装備できない。

### 2.3 合成レシピ

| ID | 材料A | 材料B | 結果 | 消費ポイント | 材料消費 |
|---|---|---|---|---:|---|
| R01 | S01 | S02 | S04 | 3 | なし |

材料は両方を習得済みであること。材料の順番は問わない。合成はプレイヤー全体の習得スキルを増やす処理で、キャラクター1体に限定しない。S04習得後は同じ合成を実行できない。S01・S02は失わず、CharacterSkillsの適性行も増減しない。

## 3. 機能仕様

### F01 起動・再開

- GASの本人限定WebアプリURLを開くと、サーバーからマスターとP001の最新状態を取得する。
- サーバー状態が読み込めるまで変更ボタンを無効にする。
- 初回は初期状態、2回目以降は最後に保存した状態を表示する。
- 保存データ不整合時は初期状態に戻さず、「記録を確認しています。大人をよんでね」と表示して変更を止める。

### F02 なかまをよぶ

- 未所有かつ有効なキャラクターをサーバーで求め、その中から等確率で1体を選ぶ。
- 費用0。初期C01を含めて最大3体。初回抽選はC02/C03各50%、2回目は残り1体100%。
- 抽選結果と所有追加を保存した後、約1秒の演出と獲得カードを表示する。
- 全種類所有時は「みんなそろったよ」と表示し、操作を無効にする。
- 画面の確率説明は未所有候補数から計算する。リクエストに抽選結果を渡さない。

### F03 じゃんけん

1. 所有仲間1体と使用可能なスキル1つを選択する。
2. グー・チョキ・パーのいずれかを押す。この時点で1対戦の要求を作る。
3. サーバーが入力と状態バージョンを検証し、CPUの手を3種類から各1/3で選ぶ。
4. 勝敗・報酬・次状態を計算し、1件の行動として保存する。
5. 自分の手、CPUの手、勝敗、基本ポイント、スキル加算、合計を表示する。

手の値は `rock` / `scissors` / `paper`。同じ手は `DRAW`、グーはチョキ、チョキはパー、パーはグーに勝つ。残りは `LOSE`。

| 勝敗 | 基本ポイント | 対応するスキルまたはS04が発動した場合 |
|---|---:|---:|
| WIN | 2 | 3 |
| DRAW | 1 | 2 |
| LOSE | 1 | 2 |

対応しないスキルを装備していた場合、加算は0。スキルなしの対戦は受け付けない。スキルによる再抽選・勝敗変更はない。乱数は娯楽用であり、金銭価値を持つ抽選には使わない。

### F04 スキル合成

- 習得済みスキルから2つ選ぶ。初期表示ではR01の材料を案内する。
- 確認欄に「S01の名前 ＋ S02の名前 → S04の名前」「3ポイント」「もとのスキルはのこる」を表示する。
- 有効レシピ、両材料の習得、結果未習得、3ポイント以上の4条件をサーバーで検証する。
- 成功時はポイントを3減らし、S04を1つ追加して保存する。既存のS01〜S03は残す。
- 成功画面にS04の事前生成済み画像を表示する。ここでGeminiを呼ばない。
- 逆順でも同じR01と判定する。同じスキル2つ、未定義ペア、ポイント不足、習得済みの結果では状態を変えない。

### F05 つながりをみる

- 「1人から、たくさんのきろく」：P001と最新10件の行動を線または一覧で表示する。対戦だけの絞り込みもできる。
- 「なかまとスキルのつながり」：3キャラ×4スキルの対応表を表示する。マスター全体を表示し、未所有・未習得を別表示する。
- キャラクター選択で、そのキャラクターのスキルを強調する。スキル選択で、それを使えるキャラクターを強調する。
- S04は合成前から適性線を表示するが、鍵アイコンと「まだおぼえていない」を添える。合成後に鍵だけが外れる。
- 「しくみの名前」を開くと、Players、Actions、Characters、Skills、CharacterSkillsとIDを表示する。
- 見えている表はAPIで取得した実データから組み立てる。図だけを固定画像で用意しない。

### F06 画像・障害時の表示

- キャラクター3枚、スキル4枚を正方形WebPとして用意する。名前・説明は画像に焼き込まずHTMLで表示する。
- 画像は1枚ずつ必要なときに取得し、取得済み画像を画面内で再利用する。
- 取得失敗時は既定の図形と名前を表示する。再取得ボタンは設けても、ゲーム状態を変更しない。
- 画像生成失敗は制作工程の問題として扱い、遊び中の対戦や合成を止めない。

## 4. 画面仕様

5画面＋結果モーダルで構成する。下部に「ホーム／なかま／じゃんけん／ごうせい／つながり」を配置する。

| ID | 画面 | 主な表示 | 操作と遷移 |
|---|---|---|---|
| UI01 | ホーム | 仲間の絵、ポイント、現在の仲間、次の遊びの案内 | 抽選ボタン、各画面への移動、再読込 |
| UI02 | なかま | 3体のカード、所有状態、使えるスキル | 所有カードを選択→じゃんけん。未所有は選べない |
| UI03 | じゃんけん | 選択仲間、スキル選択、3つの手ボタン | 手を押す→待機→結果モーダル。「もういちど」または閉じる |
| UI04 | ごうせい | 材料2枠、結果プレビュー、必要ポイント | 条件がそろえば合成→結果モーダル |
| UI05 | つながり | 記録一覧、キャラ×スキル対応表、仕組み説明 | 表の行・列を選択して対応を強調 |

通信中はすべての状態変更操作を無効にする。戻る操作は表示の切替だけで、送信済み要求を取り消さない。画面再表示時はサーバー状態を取得する。

### UIの共通条件

- 360px幅の縦画面で横スクロールを生じさせない。対応表は省略名と詳細表示で収める。
- 主ボタンのタップ領域は縦横44px以上、本文は原則16px以上。
- 絵を主役にし、説明は短い日本語。難しい用語は学習欄だけで補足する。
- 色だけで勝敗や所有を表現しない。文字・記号を併用する。
- 画像には代替テキスト。ボタンに読み上げ可能な名前。結果・エラーは読み上げ通知する。
- 音声は初版なし。動きを減らす端末設定では演出を省略する。
- パソコンではキーボードでボタンを選択でき、結果を閉じたら操作元へフォーカスを戻す。

## 5. 通信と状態

画面は `google.script.run` からサーバー関数 `api(request)` を呼び出す。REST APIとしては公開しない。完全なJSON契約は設計基礎書を参照。

| 操作名 | 目的 | 状態変更 |
|---|---|---|
| bootstrap | マスター・最新状態取得 | なし |
| drawCharacter | 未所有仲間を1体獲得 | 所有追加 |
| playRound | 1回のじゃんけん | ポイント加算 |
| synthesize | 固定レシピで習得 | ポイント消費・習得追加 |
| getRelations | 学習用の関係と最新記録取得 | なし |
| getAsset | 採用画像1枚の取得 | なし |

変更要求には一意の `requestId` と画面が読んだ `expectedVersion` を付ける。同じ要求を再送すると保存済みの結果を返し、二重に適用しない。別の操作で状態が進んでいたら更新競合として再読込を案内する。

## 6. エラー仕様

| コード | 子ども向け表示 | 状態・再操作 |
|---|---|---|
| INVALID_ARGUMENT | えらびなおしてね | 変更なし。入力を修正 |
| CHARACTER_NOT_OWNED | そのなかまはまだいないよ | 変更なし |
| SKILL_NOT_AVAILABLE | このスキルはまだつかえないよ | 変更なし |
| ALL_OWNED | みんなそろったよ | 変更なし |
| RECIPE_NOT_FOUND | このくみあわせはまだないよ | 変更なし |
| INSUFFICIENT_POINTS | あと○ポイントためよう | 変更なし。不足値を表示 |
| ALREADY_UNLOCKED | もうおぼえているよ | 変更なし |
| VERSION_CONFLICT | きろくがかわったよ。よみなおそう | 最新状態取得。自動で新規操作しない |
| REQUEST_ID_CONFLICT | つうしんをかくにんしてね | 同じIDで異なる内容。大人に案内 |
| BUSY | ちょっとまって、もういちど | 同じ要求を再送可能 |
| OP_LIMIT | きょうのデモはここまで。大人をよんでね | 200件上限。提供者が保存・初期化 |
| ASSET_UNAVAILABLE | えのよみこみにしっぱいしたよ | 代替表示。遊びは継続 |
| DATA_INTEGRITY_ERROR | きろくをかくにんしています。大人をよんでね | 変更を停止。自動初期化しない |
| INTERNAL_ERROR / 通信失敗 | つうしんをかくにんして、もういちど | 結果未確定。同じIDで再送 |

内部例外やGoogleのエラー本文、APIキー、DriveのファイルIDは子ども向け画面に表示しない。

## 7. 受入条件

次の確認は設計上の試験項目。実施日・端末・結果をアプリ実装後に記録する。

| ID | 前提・操作 | 合格条件 |
|---|---|---|
| AC01 | 新規データで起動 | C01、S01〜S03、0ポイント、version 0 |
| AC02 | 抽選を2回実行 | 重複なしで全3体。3回目はALL_OWNEDで変更なし |
| AC03 | 抽選関数へ境界値の疑似乱数を与える単体確認 | 候補2体で0は先頭、0.999999は末尾。UIは50%/50%→100% |
| AC04 | 手の全9組合せを純粋関数で確認 | 勝ち3、負け3、あいこ3。指定した対応で判定 |
| AC05 | 各スキル×各勝敗の12組を確認 | 基本点と条件付き+1が仕様表に一致 |
| AC06 | 未所有C02、またはC01＋S03を要求 | 拒否され、ポイント・行動数は変わらない |
| AC07 | 3ポイント以上でS01＋S02を合成 | ポイント-3、S04を1件追加、材料保持。全3体でS04が使用可能 |
| AC08 | 材料逆順、未定義ペア、ポイント2、S04習得済み | 逆順は同じレシピ。他条件は該当エラーで変更なし |
| AC09 | 変更要求を同じID・同じ内容で2回送る | 同じ結果を返し、Actionsは1行だけ増える |
| AC10 | 保存後の応答を意図的に捨て、再送 | CPU手・抽選結果・加減算が変わらない |
| AC11 | 同じIDで違う内容、別IDで同じ古いversionを送る | 前者はREQUEST_ID_CONFLICT、後者はVERSION_CONFLICT |
| AC12 | 2タブから同じversionで異なる変更を同時送信 | 1件だけ成功、他方は競合またはBUSY。再取得で一致 |
| AC13 | ページ再読込・ブラウザ終了後の再開 | 最新の所有・習得・ポイントを復元 |
| AC14 | 関係画面を確認 | P001の実記録と、CharacterSkillsの9本の関連が一致 |
| AC15 | 合成前後の関係画面 | S04の3本の線は同じで、習得状態だけが変化 |
| AC16 | Gemini生成→採用WebPを7枚登録 | 画像7枚が表示でき、元画像と採用画像の対応を追える |
| AC17 | 画像1枚を取得不能にする | 名前付きの代替表示になり、対戦・合成は継続 |
| AC18 | 360px幅・実機スマホで一連の操作 | 横にはみ出さず、手とスキルを押し間違えずに選べる |
| AC19 | 提供者以外のアカウント／未ログインでURLを開く | Google側でアクセス不可。Sheets・Driveも共有されていない |
| AC20 | 画面ソース・通信内容・エラー表示を確認 | APIキー、OAuthトークン、任意ファイル取得機能がない |
| AC21 | 不完全なActions行や存在しないマスターIDを検出 | 読込・変更を安全に停止し、勝手にデータを破棄しない |
| AC22 | 行動200件後に新規操作。同じ既存要求も再送 | 新規はOP_LIMIT、既存要求の再送は保存済み結果を返す |
| AC23 | バックアップからテスト用コピーへ復元 | version・ポイント・所有がバックアップ時点と一致 |

速度は実機で初回起動と通常操作を各5回測る。通常操作はおおむね3秒以内を目標とし、未達なら保存処理・画像読み込みを分けて調べる。GASの起動や回線条件があるため、保証値とはしない。

## 8. 仕様変更時の境界

キャラ・スキル・レシピを増やす場合は、ID参照、適性、確率表示、画像、受入条件を一緒に更新する。対戦効果は定義済み効果コードだけを扱い、Sheetsの任意コードやAI出力を実行しない。

複数プレイヤー、子ども本人によるログイン、公開アクセス、リアルタイム生成は本書の範囲外。初版の公開設定を緩めるだけでは対応できない。
