# 管理画面で事前生成する対戦セリフと、画像なしのゲーム

2026-10-26改訂。画像生成は廃止。利用者がプレイ中のリアルタイム生成を禁止したため、対戦結果保存後に生成する旧案も撤回する。管理画面で事前生成・確認・採用した文章だけをゲームで使う。設計採用であり、現行Web v2への実装完了ではない。

## 実行の分離

| 場面 | 処理 |
|---|---|
| 提供者の準備 | 管理画面で仲間と勝敗を選択 → 候補を生成 → 内容確認 → 採用・公開 |
| ゲーム起動 | bootstrapの既存応答に採用済みセリフ集を同梱し、ブラウザのメモリに保持 |
| 対戦 | 既存playRoundで勝敗・ポイントを保存。成功応答のキャラと勝敗から、読み込み済みの文をブラウザ内で選択・即表示 |
| 未準備・読込不良 | 組込みの定型文を即表示。生成も追加取得も行わない |

プレイ中はGeminiへの通信を一切行わない。初回起動、抽選、対戦、再送、履歴、再読込、候補不足のいずれも生成の契機にしない。旧getBattleLine案、3秒待ち、遅延応答による差替え、ROUNDごとの生成予約は廃止。ゲームのGAS通信は状態取得・ゲーム保存のために残るが、セリフ専用の追加RPCは設けない。

画像生成・画像登録・WebP変換・画像配信も撤去する。仲間3体はHTML/CSSの炎・しずく・葉の図形と名前、スキル3種は番号・名前・効果文で区別する。色だけに依存しない。勝敗・基本3スキルの得点・抽選は維持する。合成・S04・消費は[ADR 0003](../adr/0003-remove-synthesis.md)で廃止し、適性は6行固定。

## 提供者用のセリフ管理画面

ゲームの4画面とは別に、本人限定の管理画面を設ける。保護者用アカウント管理や一般公開は追加しない。

1. C01〜C03 × WIN / LOSE / DRAWの9枠を一覧表示する。各枠に下書き・採用済み・定型文のみの状態を表示する。
2. 提供者が1枠を選び「候補を生成」を押す。1回で最大3文。全9枠の自動連続生成、バックグラウンド補充、定期生成は初版に入れない。
3. 候補は下書きとして保存するだけ。生成完了でゲームへ自動反映しない。生成失敗・429・応答喪失でも現在の採用済み集を維持する。
4. 提供者が内容を確認し、採用する文を選ぶ。枠あたり1〜3文。初版は自由なプロンプト入力や文章編集を追加せず、再生成・選択・不採用に絞る。
5. 「採用内容を公開」で新しい版を保存する。下書きの版と公開版を検証し、古い管理画面からの上書きを拒否する。公開とは本人限定ゲーム内への反映であり、インターネットへの一般公開ではない。
6. 枠の採用解除も明示操作とし、解除した枠は定型文へ戻す。起動済みゲームのセリフ集は途中で差し替えず、次回bootstrapで新しい公開版を取得する。

管理画面はdoGetの管理用ルート、管理操作は別のadminApi入口に分ける。各管理要求で、サーバー設定のJANKEN_ADMIN_EMAILとSessionの実際の利用者メールを照合する。空欄・不一致は拒否し、実行者メールへの置換やクライアントの管理者フラグを認可に使わない。本人限定デプロイでもこの検証を省略しない。ゲームapiは管理操作名を受け付けない。URLを隠すだけの認可にしない。

## セリフ集とゲーム表示

- 3体×3結果の9枠、各最大3文、採用集は最大27文。欠けた枠は組込みの9種類の定型文で補う。
- 日本語1文、最大40 Unicodeコードポイント。空欄、改行、制御文字、URL、HTML、数値・ルール説明の生成を禁止する。形式チェックに加え提供者が内容を確認する。
- 固定指示は仲間の性格と想定する勝ち／負け／あいこだけから作る。実際の対戦記録、子どもの氏名・写真・自由入力・秘密情報は送らない。
- ひのこは明るく前向き、しずくは落ち着いて思いやり、このはは穏やかで好奇心を持つ。相手を傷つける表現、個人情報の要求を禁止する。
- bootstrap.dataにdialogueCatalogを追加する。形式は {version, entries:[{characterId,outcome,texts:[文字列]}]}。未公開・破損・セリフ保存先だけの読込失敗ならversion 0・空配列とし、ゲームは定型文を使う。下書き、管理者情報、モデル、生成ログ、キーを返さない。
- 対戦保存成功後、応答のresult.characterId / outcomeで枠を選び、requestIdから安定した添字を求めて表示する。同じ公開版・同じ対戦は同じ文。文の選択は乱数・勝敗・点数・Actionsを変えない。
- 採用済みAI文は「AIでつくったひとこと」、組込み文は「なかまのひとこと」と表示する。textContentで描画する。
- 文は演出でありActionsに保存しない。再送・履歴表示でも生成しない。新しい公開版を読み込んだ後は過去対戦の表示文が変わり得るが、ゲーム記録は不変。

## 保存・整合性・バックアップ

現行の物理スキーマ2はゲーム6表で、Assets/Recipes/assetIdを持たない。旧物理1は別ブックの読取り・コピー照合として保持する。マスター2の非破壊移行と切替は[データモデル](../05_data_model.md)に従う。管理データ用に同じ非公開ブックへ任意の追加2表を用意する。物理2ブックへの追加は管理者の明示初期化で行い、既存表を上書きしない。管理表が存在しなくてもゲームが起動できる。

| 表 | 内容 |
|---|---|
| DialogueDrafts | 9枠の下書き。slotKey、revision、textsJson、generationRequestId、updatedAt。生成結果の保存時も版競合を検出する |
| DialoguePublication | singleton 1行。id、version、catalogJson、updatedAt。確認済み集全体を1つのJSONとして保存する |

採用集はUTF-8で8KiB以下。ScriptLock内で公開版の比較、全件検証、1行setValues→flush→再読込照合を行う。読取りも完全な公開版だけを採用し、部分書込・不整合なら全体を定型文へ戻す。自動修復や下書きの自動採用はしない。管理操作はActions・ポイント・ゲームstate.versionを変更しない。初期化・公開・生成予約はロック取得後にも現在の接続先を照合する。生成中に接続先が変わった場合はDATASET_MISMATCHで旧DBへの結果保存を止め、予約をfailedとして残す。消費済み日次回数と429等の停止状態は保持し、同じ要求を再生成しない。保存済み採用集の構造違反はDATA_INTEGRITY_ERRORとして管理画面へ返し、ゲームは定型文を維持する。

バックアップ・復元・ハッシュ検証は追加2表も対象に拡張する。旧8表だけのバックアップも読取り照合できる。物理2へ移行・切替したブックに管理表がなければ定型文で遊べる。管理表の不具合とゲームActionsの破損を区別し、後者は従来どおり停止する。

## 管理生成の設定と再送

GEMINI_API_KEYとGEMINI_TEXT_MODELを管理生成だけで使う。JANKEN_AI_TEXT_ENABLEDは明示的trueのときだけ管理生成を許可する。falseにしても採用済みセリフはゲームで使える。JANKEN_SPREADSHEET_IDはゲーム用、JANKEN_ADMIN_EMAILは管理認可用。旧画像用2設定は参照しない。

テキストモデルの候補はgemini-3.1-flash-lite。実装時に[公式料金表](https://ai.google.dev/gemini-api/docs/pricing)とAPI仕様・アカウントでの利用可否を再確認する。課金や有料モデルへの自動切替は行わない。

生成のrequestIdはUUIDとし、接続ブックと要求内容のハッシュを併記する。同一IDの再送では保存済みの管理結果を返し、応答不明・予約だけの要求は再生成しない。同一IDで異なる入力は拒否する。意図的な再生成は提供者の新規操作だけで行う。

Script Propertiesの専用接頭辞で予約・日次回数を管理する。上限はアプリ全体で1日20試行（Asia/Tokyo）。ブック切替で回数をリセットしない。生成前に短いロック内で回数と予約を保存し、保存を確認してからロックを解放しGeminiを呼ぶ。永続化失敗なら生成しない。予約は最大200件、満杯なら管理生成を停止する。初版に自動消去・回数リセットUIは入れない。

429・認証エラー・モデル利用不可なら当日の管理生成を停止する。自動再試行はしない。管理画面には安全な状態・再読込手段を表示し、キー・生の外部応答は表示しない。管理生成の遅延や失敗は、採用済み集とゲームの動作に影響させない。
