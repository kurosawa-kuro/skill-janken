# 生成AIの対戦セリフと、画像素材を使わないゲーム設計

2026-10-26。利用者の指示により採用した再設計。画像生成はオプションとしても残さず廃止する。生成AIはゲーム内の対戦セリフに使う。本文は新仕様であり、Web v2への実装完了を意味しない。ゲーム要件はdocs/01〜08、実装作業は[実装タスク](../tasks/02_backlog/ai-battle-dialogue.md)で管理する。

## ゲームの構成

| 要素 | 採用方針 |
|---|---|
| 仲間・スキルの表現 | HTML/CSSの図形、名前、短い説明、状態ラベル。画像ファイルや画像APIなし |
| 生成AI | 保存済みの対戦結果に合わせた、仲間の短い日本語セリフ |
| 勝敗・得点・抽選・合成 | 既存のサーバー側固定ルール。AIの出力を計算や解放条件に使わない |
| 画像生成・画像登録・WebP変換・画像配信 | 製品から撤去。提供者用の隠れた生成機能も残さない |
| Drive | Sheetsの非公開確認・バックアップに必要な用途のみ。画像フォルダーは不要 |

AIセリフの実装・実生成確認をMVPに含める。一方、設定なし・無料割当超過・通信障害でも定型セリフで全ゲーム操作を続けられる。AIを設定しない起動を故障や試作品扱いにしない。ただし実生成が未確認のまま「生成AI連携まで完成」と報告しない。

## 画像なしの画面

- ホーム／仲間選択：C01ひのこは炎を表す図形、C02しずくはしずく形、C03このはは葉形。HTML/CSSで描き、名前を必ず添える。絵文字の機種差や色だけに依存しない。
- スキル選択：S01〜S04を番号・名前・効果文で表示する。例：S01「勝ったら＋1」、S02「負けても＋1」、S03「あいこで＋1」、S04「いつでも＋1」。選択可否は所有・習得・適性から判定する。
- 仲間獲得：保存成功後にカード枠と名前を表示する。イラスト完成を待つ工程、画像レア度、追加課金、素材ダウンロードはない。
- 対戦：自分とCPUの手、勝敗、基本点・加算をHTMLで確定表示し、仲間の吹き出しを添える。結果を見る／閉じる／次へ進む操作をAI待ちで無効にしない。
- 合成：S01＋S02→S04と消費3ポイントを図形と文字で示す。AIの返答や素材完成に関係なく、保存成功で解放する。
- 学習画面：実データのカード名・スキル名・線・表を使う。3体×4種の適性9行と所有・習得状態を画像なしで説明できる。

## 対戦セリフの体験

生成対象は対戦結果の一言に限定する。戦闘前の会話、チャット、自由入力、音声、長い物語、AIが考える新ルールは初版に入れない。

| 仲間 | 話し方の固定方針 | 定型セリフ例（生成失敗時にも使う） |
|---|---|---|
| ひのこ | 明るく前向き。相手をあおらない | 勝ち「やったね！つぎもたのしもう！」 |
| しずく | 落ち着き、相手を思いやる | 負け「だいじょうぶ。つぎもいっしょに！」 |
| このは | 好奇心があり、穏やか | あいこ「おんなじ手だね。つぎはどうしよう？」 |

実装では3体×勝ち／負け／あいこの9種類の定型セリフを用意する。名前・手・勝敗・点数の正確な説明は固定UIで担い、AIには数値やルール説明を生成させない。吹き出しには生成文なら「AIのひとこと」、定型文なら「なかまのひとこと」と表示し、出所を区別する。子どもにAPI・モデル名・課金設定を見せない。

## 実行順とAPI（新規設計、未実装）

1. playRoundは既存のScriptLock・Actions追記・flush・再読込確認を完了し、結果を返す。ここではGeminiを呼ばない。
2. クライアントは保存結果と定型セリフをすぐ表示する。初回成功の結果画面についてだけ、別RPCで `api({op:"getBattleLine",payload:{roundRequestId}})` を1回呼ぶ。
3. サーバーはP001の保存済みROUNDをrequestIdで引き、キャラ・手・勝敗をそこから取り出す。クライアントから結果・点数・プロンプト・モデル名を受け取らない。未知UUID・DRAW/SYNTHESIS参照は拒否する。
4. 保存済みセリフがあれば再利用。未生成なら短時間のScriptLock内で要求の予約と回数計上を保存し、ロックを解放してGeminiを呼ぶ。外部通信をゲームの保存ロック内に置かない。
5. 応答を検証してセリフを保存し、`{data:{roundRequestId,text,source:"ai"|"preset"}}` を返す。共通応答はrequestId=null、replayed=false、ゲームversionを含めない。副作用はセリフ管理と利用回数だけで、Actions・ポイント・state.versionは変えない。
6. UIは同じ対戦の結果画面が開いている場合だけ吹き出しを置き換える。3秒で表示待ちを打ち切り、遅れて届いた応答はその表示には適用しない。これは画面上の待機制限で、GASのHTTP処理のキャンセルを保証しない。

再送でplayRoundを回収したとき、再読込したとき、履歴を見たときに新規生成を自動実行しない。次の新しい対戦だけ次の生成候補になる。二重クリック・2タブから同じroundRequestIdを指定しても生成予約は1回。予約後に応答喪失した場合は生成し直さず定型文で解決する。

## モデル・設定・回数管理

2026-10-26確認の[公式料金表](https://ai.google.dev/gemini-api/docs/pricing)では、テキスト用 `gemini-3.1-flash-lite` の通常入力・出力に無料枠がある。画像用 `gemini-3.1-flash-lite-image` とは別モデル。利用アカウント・地域・割当によって呼べるかは実疎通で確認する。無料枠は無制限・永続提供・遅延保証ではない。課金の有効化や自動的な有料モデルへの切替はしない。

| Script Property | 新仕様 |
|---|---|
| JANKEN_SPREADSHEET_ID | ゲーム本体に必要 |
| GEMINI_API_KEY | テキスト生成を使う場合だけ設定。既存キーを再利用できるかは実疎通で確認 |
| GEMINI_TEXT_MODEL | テキスト専用。上記モデルを候補とする。画像モデルの設定から流用しない |
| JANKEN_AI_TEXT_ENABLED | 明示的にtrueのときだけ外部生成。未設定・falseは定型文 |
| JANKEN_DRIVE_FOLDER_ID / GEMINI_IMAGE_MODEL | 廃止。コードから参照しない。既存設定・Drive素材の削除は撤去確認後に別途行う |

アプリ側上限は1対戦1試行・1日20試行（Asia/Tokyo）を初期値とする。これはGoogle側の無料割当値ではない。429・認証エラー・モデル利用不可はその日の生成を停止し、以後は定型文。回数や停止状態をクライアントからリセットしない。自動再試行はしない。

セリフと予約はScript Propertiesの専用接頭辞に隔離し、接続ブック識別子＋ROUNDのrequestIdをキーとする。状態は予約済み／生成済み／定型文確定。予約前に日次回数を増やす。予約だけ残った要求も再生成しない。最大200対戦分で上限を設け、満杯時は定型文とする。APIキーとは別の項目として保存し、診断で内容を列挙しない。復旧や新デモでブックを変えた場合は以前のセリフを流用しない。

セリフはゲーム保存の正本ではなく、Sheetsバックアップに含めない。なくなっても状態復元と次の対戦が成立する。日次回数はブック切替でもリセットしない。上限や予約の永続化に失敗した場合は生成を呼ばず定型文を返す。

## 出力と障害時の扱い

- 入力は固定キャラの特徴と保存済み対戦の列挙値だけ。子どもの氏名・年齢・写真・自由入力・秘密情報は送らない。外部検索やツール実行は使わない。
- 日本語の短文1件、最大40文字。制御文字・改行・URL・HTML・長すぎる文・空欄・拒否応答は採用しない。文字数はUnicodeコードポイントで数える。相手を傷つける表現、個人情報の要求、数値・ゲームルールの創作を禁止する固定指示を使う。
- 出力はtextContentで描画し、HTMLやコードとして解釈しない。文字列チェックだけで内容の安全性を保証せず、勝ち／負け／あいこの実生成例を提供者が確認する。
- 生成停止・429・5xx・設定なし・長い待ち・拒否・形式不正・セリフ保存失敗は定型文。保存済みの対戦を失敗へ変更したり、再対戦を促して二重加算したりしない。
- ゲームのActions不整合は従来どおり停止する。AIの利用失敗とゲーム記録の破損を混同しない。

## 現行v2との差分と受入

v2は画像用管理関数・getAsset・画像フォルダー必須のsetup・WebP処理が残っている。今回の文書変更だけでは廃止実装済みとはしない。画像コードと管理コマンドを撤去し、通常distとGASのリモート残存ファイルを照合する必要がある。既存Assets表とassetId列は過去データの互換性のため残せるが、ゲームや表示・AIが参照しないレガシー項目とする。画像素材や既存Actionsを無断削除しない。

AC16は画像なしの7カードと全画面の識別性、AC17はAI無効／障害時のゲーム継続へ改訂する。旧AC16の画像7枚必須は廃止。AIの実生成はAC24、保存と表示順・遅延応答はAC25、回数制限・重複防止はAC26で新規に検証する。旧試験結果を新条件のPASSへ読み替えない。
