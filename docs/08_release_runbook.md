## 配置と公開制限

### 管理関数の一時実行

内部関数は末尾 `_` のため、GASエディタの実行候補にも表示されない。管理者だけが利用する一時ラッパーを用意し、実行後に除去する。通常ソース・バージョン・Web配置に管理用の公開関数を残さない。[Google公式の説明](https://googleappsscript.blogspot.com/2010/06/hiding-helper-functions.html)。

1. ルートで `npm run check`。`.clasp.json` のscriptIdが今回の専用GAS、rootDirがdistであることを確認する。
2. `node scripts/operator.mjs setup` は初期化用。backup/restore/verifyは保存検証用。旧generate/inspect（画像用）/registerは廃止対象として今後実行しない。画像設定への依存除去は新タスクで実装する。テキスト疎通は管理画面での事前生成→確認→公開で検証する。プレイ中の生成は禁止。
3. PowerShellで `Push-Location artifacts/operator`、`..\..\node_modules\.bin\clasp.cmd push --force`、`Pop-Location` を順に実行する。clasp 3.4.1では相対 `-P` のルート検証で失敗する場合があるため、そのディレクトリで実行する。
4. GASエディタを再読込し、server/operator-run.gsの `operatorRun` を1回実行する。初回はGoogle側の権限を確認して認可する。ログは成功概要だけとし、キー・応答本文は出さない。
5. 実行完了後、**エディタでserver/operator-run.gsを削除**し、ルートから `npx clasp push --force` を実行する。再読込し、一時ファイルがないことを確認する。
6. 一時ファイルがある間はバージョン作成・デプロイをしない。必要時は通常24ファイルに復帰した後で `npx clasp create-deployment --description '確認内容'` を実行する。既存配置の更新にはそのdeploymentIdを指定し、公開範囲を再確認する。

clasp 3.4.1の `--force` はmanifestの上書き指定であり、**リモート側だけに残ったファイルの削除を検出しない**。今回、単純なpushは「already up to date」となった。その後、通常ソースの変更を含む19ファイルをpushし、エディタから一時ファイルが消えたことを確認してからv1を配置した。復帰確認を省略しない。

`setupLab_` は新規ブック作成直後にIDを保存する。途中失敗時も無条件に別ブックを作り直さず、設定済みデータの整合性エラーとして停止する。既存ブックを消してやり直す処理は持たない。

### 現在の試験配置（2026-10-26）

専用の接続先・Web版v1・観測結果は[②の実測記録](tasks/03_active/foundation-02-integration.md)に記載。manifestは `access: MYSELF`、`executeAs: USER_DEPLOYING`。Sheetsと画像フォルダーは所有者1名・shared=falseを確認した。GASから初期状態を読み、本人ブラウザで表示・再読込できた。テスト用WebPの配信も確認済み。Geminiのモデル一覧取得は成功したが、旧画像生成はHTTP 429。その後の再設計で画像生成を廃止し、課金・割当の解消待ちは取り消した。別アカウント拒否・ゲーム操作は未確認であり、リリース完了ではない。

③では検証用関数を撤去した後、clasp pullによる24ファイルの通常distとの一致を確認し、同じdeploymentIdをv2へ更新した。初期表示・再読込は実ブラウザで成功。保存・再送・復元の実測と未確認範囲は[③の記録](tasks/03_active/foundation-03-hardening.md)を参照する。

### 初版の配置

1. 提供者のアカウントでSheetsとDriveフォルダーを作り、共有を制限する。
2. GASにSpreadsheet ID、Driveの保存先、Geminiキー、モデルIDを設定する。
3. 提供者が必要な権限を確認して初回認可する。Sheets・Drive・ユーザー情報に加え、Gemini呼出しには外部サービスへの接続（script.external_request）が必要。一部の許可だけで初期画面が動いても、管理画面のテキスト生成は別途失敗し得る。
4. Webアプリを実行ユーザー「自分」、アクセス範囲「自分のみ」に相当する設定でデプロイする。
5. 提供者のスマホで動作を確認し、別アカウントからはアクセス不可であることを確認する。

利用するアカウント種別や組織ポリシーによって利用可能な公開設定が異なる。本人限定を選べない場合、安易に公開範囲を広げず、開発用の本人アクセスで試す。実行ユーザーとアクセス権の意味は[公式Webアプリ資料](https://developers.google.com/apps-script/guides/web)を参照する。

### 実装上の制限

- APIキーをHTML・Sheets・ブラウザ保存領域に入れない。Script Propertiesはスクリプト編集者が扱えるため、編集者を提供者に限定する。
- apiに任意のplayerId、Drive fileId、スプレッドシート名、任意URLを指定する機能を作らない。
- 手、所有、適性、得点はサーバーで検証・計算する。クライアントが送る勝敗や加算値は採用しない。
- 名前・エラー表示はtextContent等で挿入し、シート文字列をHTMLとして解釈しない。
- リクエストのサイズを制限し、個人情報・認証情報をログに残さない。
- キャッシュは性能向上の補助に限り、最新状態や重複判定の正本にしない。
- 「URLを知っている人だけ」「隠した管理ボタン」だけを認可とみなさない。

一般公開する場合は認証済み主体とplayerIdのサーバー側対応、各操作の所有権確認、レート制限、利用上限、ログと削除運用を別途設計する。本人限定のapiをそのまま匿名公開しない。

## デプロイ後smoke（Golden Path）

[要件](01_requirements.md)と同じ7ステップを、初期化済みの確認用データで実行する。既存のデモ記録を試験の都合で無断初期化しない。以下は操作手順の具体化であり、実施結果は未記録。

| # | 操作 | 期待する観測結果 |
|---|---|---|
| 1 | 提供者のスマホでURLを開く | P001、C01、S01〜S03、0ポイント、version 0が表示 |
| 2 | 「なかまをよぶ」を2回押す | 全3体、重複なし。3回目は無効。各成功でActionsが1行増える |
| 3 | C01＋S01で対戦し、仲間や適性スキルを変えて試す | 手・勝敗・基本点・加算・累計スコアが仕様どおり。二重押下で重複保存されない |
| 4 | 「つながり」を開き、仲間とスキルを選ぶ | 最新10件と6本の適性が一致。仲間獲得後も線は同じで所有表示だけ変わる |
| 5 | 再読込・再開する | 最新version・累計スコア・所有・初期習得3種が一致 |

別アカウントと未ログインからのアクセス拒否も確認する。画像なしのカードは改訂AC16、AI停止時継続は改訂AC17、管理画面の実生成・プレイ中の生成ゼロ・管理生成の回数管理はAC24〜AC26、復元はAC23で確認する。個別関数の成功だけでリリース完了としない。

## デモ運用・障害対応

| 場面 | 提供者の手順 |
|---|---|
| デモ開始前 | マスター・画像なしカード・初期データ・公開範囲・採用済みセリフ集と管理認可を確認 |
| 日々の確認 | Apps Scriptの実行失敗、Actions件数、AIセリフの日次回数・停止状態を確認 |
| 保存前後 | デモ前とデモ終了時にSheetsを日時付きでコピー。マスター変更前にも保存 |
| 通信失敗 | 同じ要求の再送で確認。記録を見ずにポイントを手修正しない |
| 不完全行 | 利用停止→Sheetsコピー→requestIdと直前状態を照合→テスト用コピーで修復検証 |
| AIセリフだけ失敗 | ゲームは採用済み文／定型文で続行。提供者が管理画面のテキストモデル・割当・停止状態を確認し、自動再試行しない |
| 200件到達 | Sheetsをコピーしてデモ記録を保管し、管理関数でP001のActionsだけを初期化 |
| リセット時 | 端末の保留要求を消し、タブを閉じて開き直す。古いタブからの送信を防ぐ |
| 復元 | バックアップコピーでマスター版と全行を検証し、テスト用GASから先に確認 |
| デモ終了後 | 試遊記録は原則30日で見直し、不要なコピーも削除。画像素材は別管理 |

初版には削除・復旧用の子ども向けボタンを置かない。バックアップは変更履歴の代替として保管するが、これだけで無停止運用を保証しない。

Apps Scriptや関連サービスには実行時間・呼出し数等の割当があり、上限はアカウント種別等で異なる。数値を固定前提にせず[公式クォータ一覧](https://developers.google.com/apps-script/guides/services/quotas)を実装日に確認する。200件は本アプリの設計上の上限であり、Googleの保証された容量上限ではない。

## 利用停止・復旧・ロールバックの判断

以下は元の設計にある「利用停止→コピー→照合→テスト用コピーで検証」を実行順に整理した手順案。コード版の戻し方や配置コマンドは、GASへの配置方式を決めた実装タスクで追記・検証する。

1. Golden Pathの破綻、二重加算、不完全行、公開範囲の誤りを検出したら試遊を停止する。提供者が状況を確認するまで変更操作を続けない。
2. 失敗時点のSheetsをコピーし、requestId・直前状態・実装版・マスター版を照合する。元データを消さず、結果不明の要求を別IDで再実行しない。
3. 完全な行が保存済みなら同一要求の再送で回収する。不完全行の場合はテスト用コピーで修復またはバックアップ復元を検証する。
4. 復元先でマスター版と全行の整合性を確認し、バックアップ時点のversion・ポイント・所有・習得が一致することを確認する（AC23）。問題のあるコピーをそのまま利用再開しない。
5. コードを戻す必要がある場合は、戻す版とデータ・マスターの互換性を検証する。初版で検証済みの旧版がない場合は利用停止を維持する。設定だけで公開範囲を広げて回避しない。
6. 提供者が検証済みの状態で再開し、古い保留要求を消してタブを開き直す。復旧記録と再確認結果をタスクに残す。

バックアップ後に行われた変更がある場合、どこまで復元できたかを明記する。バックアップだけで無停止・無損失を保証しない。リセットは記録保管後に管理関数でP001のActionsだけを対象とし、キャラ・スキル等のマスターを消さない。

## 試遊と記録の見直し

大人の説明付きで5〜10分試遊し、次に押す場所、スキルと得点の関係、同じスキルが複数の仲間につながることへの気づきを観察する。子どもの氏名・年齢・写真は記録しない。試遊記録は原則30日で見直し、不要なバックアップコピーも削除する。旧画像素材は保管用であり、ゲームは参照しない。

## リリース後の作業

未解決事項・実施できなかった検証・復旧中の判断を[タスク一覧](tasks/README.md)から追跡する。恒久手順は本書等へ反映する。一般公開、個別プレイヤー、学校全体の同時利用は別設計であり、本人限定のapiを公開設定の変更だけで匿名公開しない。

### 合成廃止版への接続切替

新規版2ブックで試験し、旧版1は保管する。旧記録のコピー・ハッシュ照合後に提供者が明示的に接続先を切り替える。旧ブックを自動上書き・自動リセットしない。旧保留要求を新ブックへ再送しない。復元検証では版1のS04・SYNTHESISを旧ルールで照合し、新ゲームは版1への書込を拒否する。[データモデル](05_data_model.md)を参照。今回この切替は未実施。

### テキストAIの疎通と停止

新設計ではGEMINI_TEXT_MODELと有効化設定を使う。画像モデルの429を解消するための課金・再試行は行わない。画像用キー設定が残っていても画像APIを呼ばない実装へ移行する。

テキストAIの設定は管理画面での事前生成だけに使う。無効・429・認証・モデル利用不可でも既存採用集を保持し、ゲームは採用文または定型文で動く。管理画面で実生成→内容確認→公開を検証し、全プレイ操作に生成呼出し・セリフ専用RPCがないことを確認する。詳細は[設計](specs/ai-battle-dialogue.md)。追加の管理2表はバックアップ・復元照合に含め、旧8表だけの復元も検証する。
### ③のバックアップ・復元検証コマンド

正常データは `backupLab_()` でロック内に全表検証→Sheetsの `Spreadsheet.copy(name)` →非公開所有確認→全表再検証→SHA-256一致確認を行う。[公式のcopyと必要権限](https://developers.google.com/apps-script/reference/spreadsheet/spreadsheet#copyname)を2026-10-26確認。Drive全体の書込権限を追加する必要はない。書式を含むブックコピーだが、検証対象の正本は8表の値と型。画像はファイルID参照のままで、Drive画像本体・GASコード・Script Propertiesはこのバックアップに含めない。

`restoreBackupToCopy_(backupId)` はバックアップから新しい検証用ブックを作り、現用ブックを上書きせず、JANKEN_SPREADSHEET_IDも変更しない。現用IDを直接指定すると拒否する。作成方法はdocs/04のoperator backup/restore/verifyを参照。検証失敗時の途中コピーは証跡として残り、成功扱いにしない。

元データが破損している場合、この正常データ用コマンドはコピー前に停止する。先に提供者がGoogle Sheets画面から現状の証跡コピーを保存し、既知の正常バックアップを別ブックへ復元する。利用再開にはデモ停止中に復元先の版・ポイント・所有・習得を照合し、提供者が接続先を切り替えて保留要求を整理する。本番切替・リセット・破損行の自動修復は③では実装しない。

## マスター版2への実反映（実行前）

2026-10-26のローカル実装は検証済みだが実GAS未反映。具体的な切替・設定・受入チェックは[配置タスク](tasks/03_active/mvp-release-verification.md)。`create` は新規ブックだけを作り、`activate NEW_ID OLD_ID` は想定接続先を検証して旧ブックをバックアップした後に切替える。通常distと一時operatorを混在させず、版作成前にリモートを読戻して30ファイルとの完全一致を確認する。旧Assetsや旧Actionsを削除しない。管理画面は `?view=admin`。実機・別アカウント・テキスト実生成が確認できるまでは最終受入未完了とする。
