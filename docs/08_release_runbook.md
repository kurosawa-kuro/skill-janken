## 対象と実施前提

提供者の管理端末・本人限定公開・P001の1プレイヤー・行動200件までの短期デモを対象とする。以下は実装後に実施する手順。デプロイ、共有変更、画像生成、リセット、復旧を今回の文書作業で実施したものではない。

- [AC01〜AC23](07_test_strategy.md)の結果・端末・日時・証拠を記録する。検証用の本人限定配置を使って試験し、未実施の項目を残したままデモ完成と判定しない。
- マスター参照、CharacterSkills 9行、R01 1行、初期状態、採用WebP7枚、公開範囲を確認する。デモ前とマスター変更前にSheetsを日時付きでコピーする。
- Script Properties、GAS・Sheets・Driveの編集権限、画像の版を確認する。キーを子ども向け画面やログへ出さない。
- 実装版、設定・マスター版、バックアップの参照、テスト結果を提供者用の記録に残す。子どもの個人情報や認証情報を含めない。

## 配置と公開制限

### 初版の配置

1. 提供者のアカウントでSheetsとDriveフォルダーを作り、共有を制限する。
2. GASにSpreadsheet ID、Driveの保存先、Geminiキー、モデルIDを設定する。
3. 提供者が必要な権限を確認して初回認可する。
4. Webアプリを実行ユーザー「自分」、アクセス範囲「自分のみ」に相当する設定でデプロイする。
5. 提供者のスマホで動作を確認し、別アカウントからはアクセス不可であることを確認する。

利用するアカウント種別や組織ポリシーによって利用可能な公開設定が異なる。本人限定を選べない場合、安易に公開範囲を広げず、開発用の本人アクセスで試す。実行ユーザーとアクセス権の意味は[公式Webアプリ資料](https://developers.google.com/apps-script/guides/web)を参照する。

### 実装上の制限

- APIキーをHTML・Sheets・ブラウザ保存領域に入れない。Script Propertiesはスクリプト編集者が扱えるため、編集者を提供者に限定する。
- apiに任意のplayerId、Drive fileId、スプレッドシート名、任意URLを指定する機能を作らない。
- 手、スキル、レシピ、ポイントはサーバーで検証・計算する。クライアントが送る勝敗や加算値は採用しない。
- 名前・エラー表示はtextContent等で挿入し、シート文字列をHTMLとして解釈しない。
- リクエストのサイズを制限し、個人情報・認証情報をログに残さない。
- キャッシュは性能向上の補助に限り、最新状態や重複判定の正本にしない。
- 「URLを知っている人だけ」「隠した管理ボタン」だけを認可とみなさない。

一般公開する場合は認証済み主体とplayerIdのサーバー側対応、各操作の所有権確認、レート制限、利用上限、ログと削除運用を別途設計する。本人限定のapiをそのまま匿名公開しない。

## デプロイ後smoke（Golden Path）

[要件](01_requirements.md)と同じ7ステップを、初期化済みの確認用データで実行する。既存のデモ記録を試験の都合で無断初期化しない。以下は操作手順の具体化であり、実施結果は未記録。

| # | 操作 | 期待する観測結果 |
|---|---|---|
| 1 | 提供者のスマホでURLを開く | P001、C01、S01〜S03、0ポイント、version 0が表示 |
| 2 | 「なかまをよぶ」を2回押す | 全3体、重複なし。3回目は無効。各成功でActionsが1行増える |
| 3 | C01＋S01で対戦し、合計3ポイント以上まで繰り返す | CPU手・勝敗・基本点・加算が仕様どおり。通信中の再タップで二重保存されない |
| 4 | S01＋S02を合成する | ポイント-3、S04追加、材料保持、Actions 1行追加 |
| 5 | S04を装備して再度対戦する | 結果にかかわらず基本点+1。合成の再実行はできない |
| 6 | 「つながり」を開き、キャラとスキルを選択する | 最新10件と9本の適性が実データに一致。S04の線は変わらず鍵だけ外れる |
| 7 | ページ再読込・ブラウザを閉じて再開する | 最新のversion・ポイント・所有・習得が保存状態と一致 |

別アカウントと未ログインからのアクセス拒否も確認する。画像7枚と画像失敗時の継続はAC16・AC17、復元はAC23で確認する。個別の関数が動くことだけをもってリリース完了としない。

## デモ運用・障害対応

| 場面 | 提供者の手順 |
|---|---|
| デモ開始前 | マスター参照・画像7枚・初期データ・公開範囲を確認 |
| 日々の確認 | Apps Scriptの実行失敗、Actions件数、Gemini制作時の利用量を確認 |
| 保存前後 | デモ前とデモ終了時にSheetsを日時付きでコピー。マスター変更前にも保存 |
| 通信失敗 | 同じ要求の再送で確認。記録を見ずにポイントを手修正しない |
| 不完全行 | 利用停止→Sheetsコピー→requestIdと直前状態を照合→テスト用コピーで修復検証 |
| 画像失敗 | 代替表示で続行し、AssetsとDrive権限を確認 |
| 200件到達 | Sheetsをコピーしてデモ記録を保管し、管理関数でP001のActionsだけを初期化 |
| リセット時 | 端末の保留要求を消し、タブを閉じて開き直す。古いタブからの送信を防ぐ |
| 復元 | バックアップコピーでマスター版と全行を検証し、テスト用GASから先に確認 |
| デモ終了後 | 試遊記録は原則30日で見直し、不要なコピーも削除。画像素材は別管理 |

初版には削除・復旧用の子ども向けボタンを置かない。バックアップは変更履歴の代替として保管するが、これだけで無停止運用を保証しない。

Apps Scriptや関連サービスには実行時間・呼出し数等の割当があり、上限はアカウント種別等で異なる。数値を固定前提にせず[公式クォータ一覧](https://developers.google.com/apps-script/guides/services/quotas)を実装日に確認する。200件は本アプリの設計上の上限であり、Googleの保証された容量上限ではない。

## 利用停止・復旧・ロールバックの判断

以下は元の設計にある「利用停止→コピー→照合→テスト用コピーで検証」を実行順に整理した手順案。コード版の戻し方や配置コマンドは、GASへの配置方式を決めた実装タスクで追記・検証する。

1. Golden Pathの破綻、二重加算、不完全行、公開範囲の誤りを検出したら試遊を停止する。提供者が状況を確認するまで変更操作を続けない。
2. 失敗時点のSheetsをコピーし、requestId・直前状態・実装版・マスター版を照合する。元データを消さず、結果不明の要求を別IDで再実行しない。
3. 完全な行が保存済みなら同一要求の再送で回収する。不完全行の場合はテスト用コピーで修復またはバックアップ復元を検証する。
4. 復元先でマスター版と全行の整合性を確認し、バックアップ時点のversion・ポイント・所有・習得が一致することを確認する（AC23）。問題のあるコピーをそのまま利用再開しない。
5. コードを戻す必要がある場合は、戻す版とデータ・マスターの互換性を検証する。初版で検証済みの旧版がない場合は利用停止を維持する。設定だけで公開範囲を広げて回避しない。
6. 提供者が検証済みの状態で再開し、古い保留要求を消してタブを開き直す。復旧記録と再確認結果をタスクに残す。

バックアップ後に行われた変更がある場合、どこまで復元できたかを明記する。バックアップだけで無停止・無損失を保証しない。リセットは記録保管後に管理関数でP001のActionsだけを対象とし、キャラ・スキル等のマスターを消さない。

## 試遊と記録の見直し

大人の説明付きで5〜10分試遊し、次に押す場所、合成後の変化、同じスキルが複数の仲間につながることへの気づきを観察する。子どもの氏名・年齢・写真は記録しない。試遊記録は原則30日で見直し、不要なバックアップコピーも削除する。画像素材は別管理する。
