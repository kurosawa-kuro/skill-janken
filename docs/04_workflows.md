## 現在の開発環境

2026-10-26：ゲーム基本機能と管理画面のAIセリフ事前生成はローカル実装済み。続いてDBを物理スキーマ2（ゲーム6表・型付きActions）へ再設計し、旧形式の読取りと非破壊移行を実装した。最新変更は未検証・実GAS未反映。46件PASSは5b6bb44時点の過去記録であり、最新変更の合格を示さない。

Node.js 22以上を用意し、プロジェクトルートで実行する。検証環境はWindows・Node.js v24.21.0・npm 11.19.0。依存バージョンはpackage-lock.jsonで固定する。

Chromiumが既に導入済みならブラウザのインストールは不要。初回ダウンロードを含む環境準備と、外部サービスへの接続は別である。

### ②の接続設定

専用GAS・Sheets・Driveを作成し、.clasp.jsonは今回のGASとdistを指す（Git対象外）。JANKEN_の2設定は保存済み。Geminiのキーは提供者が設定し、モデル名も保存済み。外部通信を追加認可してモデル一覧取得に成功したが、画像生成はHTTP 429。[②のタスク](tasks/03_active/foundation-02-integration.md)に接続先と実測を記録する。claspは3.4.1で固定した。

| Script Property | 用途 |
|---|---|
| JANKEN_SPREADSHEET_ID | ゲーム6表と任意のセリフ管理2表を置くブック |
| JANKEN_DRIVE_FOLDER_ID | 廃止。新コードは参照しない |
| GEMINI_API_KEY | 管理画面で事前生成する場合のみ必要。既存値を表示・コピーしない |
| GEMINI_IMAGE_MODEL | 廃止。GEMINI_TEXT_MODELへコード上で流用しない |
| JANKEN_ADMIN_EMAIL | 管理要求の利用者照合。空欄・不一致では管理操作を拒否 |
| GEMINI_TEXT_MODEL | テキスト用モデル。許可値gemini-3.1-flash-lite |
| JANKEN_AI_TEXT_ENABLED | 明示的trueで管理生成を許可。falseでも採用済み集は使用可能。ローカル実装済み |

`inspectConfiguration_()` は名前と設定有無だけを返す内部診断。値は返さず、設定の書換えもしない。外部アダプターは実装済み。設定の存在だけでは疎通成功とせず、実データで確認する。元アプリのScript ID・Deployment ID・接続設定をコピーしない。

### ③の管理コマンドと画像処理の廃止

旧scripts/convert-webp.mjsは撤去済み。画像制作・アップロード・登録を新しいセットアップ手順に含めない。

`npm run build` 後の `node scripts/operator.mjs backup` は検証済みバックアップ、`restore BACKUP_ID` は別コピーへの復元検証、`verify` は試験用コピーだけに決定的な1行を追記して再送・バックアップ・復元を確認するエディタ専用ビルドを作る。verifyはコピー3冊を作り、元の接続先やActionsを変えない。200件に達した元データでは追加試験できない。

実行は従来どおりartifacts/operatorからclasp push、エディタのoperatorRunを1回実行する。終了後はエディタでserver/operator-run.gsを削除して通常distをpushし、存在しないことを確認する。管理ビルドからデプロイ・版作成をしない。生成HTTP 429の再試行や課金設定変更をこれらの操作に含めない。

### 提供者用セリフ設定コマンド

`node scripts/operator.mjs configure EMAIL true` は、GASエディタの実利用者メールとEMAILが一致する場合だけ管理者・テキストモデル・生成有効化を設定するエディタ専用ビルドを作る。`false` で生成を無効化できる。GEMINI_API_KEYは既存値を保持し、返却・ログ出力・引数での受渡しをしない。trueへの変更は既存キーがある場合だけ。生成予約・日次カウントは削除しない。このコマンドの作成や設定自体でGeminiへ接続・生成しない。

2026-10-26の追加実装は整形だけを行い、利用者指示によりテスト・build・ブラウザー・実GAS検証を実行していない。最終検証は実装完了後にまとめる。

### 物理スキーマ2の作成・移行コマンド

`create`は新しい6表の空ゲームを作り、接続先を変えない。旧物理1・マスター2の進行を引き継ぐ場合は `node scripts/operator.mjs migrate SOURCE_ID` を使う。バックアップ後に別ブックへ変換し、旧履歴・進行・管理2表の一致を照合する。成功後も `activate NEW_ID OLD_ID` は別操作。旧マスター1の合成履歴は移行せず保管する。手順・復旧条件は[08](08_release_runbook.md)を参照。現時点ではこれらの新処理を実行していない。
