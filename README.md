# スキルじゃんけんラボ

仲間を集め、基本スキルを選んでCPUとじゃんけんし、累計スコアを伸ばす教育用Webアプリです。遊びの記録と仲間・スキルの対応表で、データの「1対多」「多対多」を学びます。

2026-10-26：合成・画像機能を撤去し、3スキル・6適性のゲーム4画面、保存・再送、学習表示、管理画面でのAIセリフ事前生成・採用をローカル実装済み。npm run check（46テスト・30実行ファイルのビルド・360px幅Chromium）が成功。実GASは従来のWeb v2のまま。新ブックへの切替・新コード配置・Gemini実生成・実機と別アカウントの確認は未完了。 詳細は[実装・検証記録](docs/tasks/03_active/mvp-release-verification.md)。

## 初版の体験と範囲

1. 「なかまをよぶ」で、未所有の仲間を無料で獲得する。
2. 所有する仲間1体と、その仲間が使えるスキル1つを選ぶ。
3. グー・チョキ・パーを押し、CPUと1手で勝負する。
4. 探究ポイントを累計スコアとして積み上げる。消費や交換はありません。
5. 「つながり」で対戦記録と、仲間3体・基本スキル3種の対応を見る。

| 項目 | 初版の設計 |
|---|---|
| 対象 | 小学校中〜高学年を仮対象とし、大人が伴走 |
| 利用形態 | 提供者の管理端末、本人限定公開、縦画面スマートフォン中心 |
| プレイヤー | P001「たんけんたい」1人。交代時も同じ記録を使用 |
| 仲間 | C01「ひのこ」、C02「しずく」、C03「このは」の3体 |
| 抽選 | 最初はC01を所有。残り2体を未所有から等確率・重複なしで獲得 |
| スキル | 基本3種を初期習得。適性のある1つを装備。追加解放なし |
| ポイント | 勝ち2点、あいこ・負け1点。スキルの条件を満たすと+1 |
| スコア | 対戦の獲得点を累計表示。消費・交換・解放条件なし |
| 画面 | ホーム／なかま／じゃんけん／つながり＋結果モーダル |
| 保存 | 所有・習得・ポイント・行動記録。成功した変更は200件まで |
| 表現・生成AI | 画像なしの名前・図形カード。管理画面で事前生成・採用したセリフを対戦結果に応じて表示 |

初期状態はC01所有、S01〜S03習得、0ポイント、version 0。S01は勝ち、S02は負け、S03はあいこで+1です。スキルは勝敗を変更しません。合成・S04・レシピ・ポイント消費は廃止しました（旧版の保管用検証のみ保持）。

3種は最初から習得済み。「適性」は仲間とスキルの対応で、CharacterSkillsは6行固定です。仲間を獲得しても適性は変わりません。

初版の対象外は、課金、広告、対人戦、ランキング、チャット、ユーザー登録、複数プレイヤー、一般公開、自由入力プロンプト、画像生成、スキル合成、AIによるゲーム効果決定、リアルタイム同期、教材販売、保護者管理画面です。

## 学べるデータのつながり

| テーマ | アプリ内の表示 |
|---|---|
| 1対多 | 1人のPlayersにひも付くActionsの最新10件。対戦だけの絞り込みも可能 |
| 多対多 | Characters 3体とSkills 3種を結ぶCharacterSkillsの対応表 |
| 中間テーブル | 対応表の1行が1本のつながりになることを、キャラ・スキルの選択で強調 |
| IDによる参照 | 「しくみの名前」で表名とIDを確認 |

学習画面はAPIの実データで構成します。所有する仲間が増えても適性6本は変わらず、1つのスキルを2体が使えることを確認できます。

## 技術と保存設計

| 技術 | 役割 |
|---|---|
| Google Apps Script（GAS / JavaScript） | HTML Serviceによる画面配信、入力検証、勝敗・ポイント計算、保存 |
| HTML / CSS / JavaScript | スマホ向け4画面、カード、結果表示、学習画面 |
| Google Sheets | 8シートのマスター・初期状態・行動記録 |
| Google Drive | Sheetsの非公開確認・バックアップ。画像フォルダーは新仕様では不要 |
| Gemini | 管理画面でキャラ×勝敗の短文を事前生成。プレイ中の生成・画像生成はしない |

画面はdoGetが配信し、ゲームapiはbootstrap・drawCharacter・playRound・getRelationsの4操作。bootstrapに採用済みセリフ集を同梱し、対戦後はブラウザ内で選んで表示します。管理画面とadminApiは別に設け、サーバーで管理者を検証します。旧getAssetとgetBattleLine案は廃止。ローカル実装済みです。

Sheetsには `Players`、`Characters`、`Skills`、`CharacterSkills`、`Recipes`、`Assets`、`Actions`、`Settings` を置きます。成功した変更ごとに入力・結果・次状態をActionsへ1行追記し、最新行の `stateJson` を現在状態とします。行が0件のときだけPlayersの初期状態を使い、現在状態を別表へ二重保存しません。

`ScriptLock`、`requestId`、`expectedVersion` で排他・再送・競合を扱います。同じ要求の再送は保存済みの結果を返し、抽選・加減算を繰り返しません。不完全行や参照不整合では変更を止め、自動で初期化しません。SheetsにDB同等のトランザクションを保証させる設計ではありません。

## 開発の準備

Node.js 22以上を用意し、プロジェクトルートで実行します。

```powershell
npm ci
npx playwright install chromium
npm run check
npm run preview
```

Chromiumが導入済みならインストールは不要です。プレビューは `http://127.0.0.1:4173/` の仮データ表示で、Ctrl+Cで終了します。`npm run check` は整形確認・46件のローカルテスト・ビルド・ブラウザ確認を行います。`npm run build` の出力はdistで、アップロードやデプロイはしません。Makefileはnpmのラッパーです。

ローカルでゲームを試すにはプレビューを開きます。管理画面は `/?view=admin`。実環境の残作業は[配置・受入](docs/tasks/03_active/mvp-release-verification.md)を参照。

1. 提供者のGoogleアカウントでGAS・Sheetsを準備します。画像生成環境・画像フォルダーは新仕様では不要です。
2. 基本設定はSpreadsheet ID。管理者メールとテキストAI設定は事前生成の管理機能だけで使います。AI設定なしでもゲームは採用済み文または定型文で動きます。実環境への設定は配置時に確認します。
3. マスター検証、勝敗・得点・抽選の純粋関数、保存・再送処理を実装する。
4. 画像なしの4画面と学習画面をつなぎ、管理画面でセリフを作成・確認・公開します。ゲームは起動時に採用集を読み込み、対戦中に生成しません。
5. 本人限定設定で配置し、受入条件・実機操作・バックアップ復元を確認する。

`env/` と `doppler.yaml` は既存の開発用ひな形です。GASへの設定同期は未実装で、初版の実行時設定はScript Propertiesを使います。ローカル秘密情報をコミットしません。テキスト生成モデル・料金・公開設定・サービスの割当は実装時に公式資料で確認します。

## 画像・公開・運用

- 画像生成・画像アップロード・WebP制作・getAsset配信は製品コードから撤去済みです。標準の図形・名前・効果文だけで遊べる仕様です。
- 提供者が管理画面でAIセリフを事前生成・採用します。ゲームは取得済みの文を結果に合わせて表示し、追加通信・自動生成を行いません。採用文がなければ定型文。画像生成は廃止です。
- GASは実行ユーザー「自分」、アクセス範囲「自分のみ」に相当する設定とし、Sheets・Driveも非公開にします。子どもには管理端末上でアプリを見せ、提供者の認証情報は渡しません。
- デモ前後とマスター変更前にSheetsをコピーします。200件到達時は提供者が記録を保管して初期化し、端末の保留要求を消してタブを開き直します。復旧はテスト用コピーで検証します。
- 試遊では子どもの氏名・年齢・写真を記録せず、記録は原則30日で見直します。一般公開や個別プレイヤーへの拡張は別途設計します。
